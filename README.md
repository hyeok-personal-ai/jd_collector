# Recruit Radar / jd_collector

공개 채용 경로를 확인하고 공고를 수집·검색하는 로컬 Python 앱의 소스 기록입니다.
운영 데이터, 실제 공고 본문, 개인 설정 및 인증정보는 포함하지 않습니다.

## 실행

Python 3.11 이상이 필요합니다.

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -e ".[dev,analysis]"
python -X utf8 -m app.launcher
```

브라우저에서 http://127.0.0.1:8000/ 을 엽니다. Windows에서는 `./start.ps1`도 사용할 수 있습니다.
새 실행은 빈 DB로 시작합니다. 서버의 수집 설정에서 출처와 자동 수집을 확인하세요.
`.env.example`은 설정 참고용이며 앱이 자동으로 읽지는 않습니다. 필요한 값은 환경변수로 설정합니다.

## 검증

```sh
python scripts/check_publication.py
python -X utf8 -m pytest -q
python -X utf8 -m app.offline_replay
```

테스트 데이터는 합성 샘플입니다. 실제 사이트 응답을 요구하는 테스트는 해당 자료가 없어 건너뜁니다.
GitHub Actions는 Linux/Windows, Python 3.11/3.12에서 공개 파일 점검·테스트·오프라인 재현을 실행합니다.
실제 사이트 수집, 로컬 DB 동기화, 운영 데이터 업로드는 실행하지 않습니다.

## 현재 구현 범위

- 직행: 공개 기업 첫 목록·관련 공고·최근 공식 사이트맵에서 개발 후보 발견, 공개 본문 및 상태 반영, 이어받기.
- 인디스워크: 공개 모집 분류 동기화. WordPress/CDN 보안 검증이 발생하면 중단하고 재확인 대기.
- 확정 마감일의 로컬 만료 처리, 상시·조기마감·미확인 기한의 원문 재확인.
- 검색·필터·즐겨찾기·CSV·로컬 백업과 수집 현황.
- 공개 ATS 및 기업별 경로의 일부 어댑터. 전체 기업 및 전체 개발 공고 수집 완료는 아닙니다.

사이트의 접근 정책과 이용 조건을 확인하고 사용해야 합니다. robots 확인 실패·로그인·보안 검증은 우회하지 않습니다.
공개 URL이 있다는 이유만으로 본문 재배포 권한이 생기는 것은 아닙니다.
수집 결과는 원문과 대조하세요. 전체 공고 확보와 실시간 정확성을 보장하지 않습니다.

공개 범위와 제외 기준은 [PUBLICATION.md](PUBLICATION.md), 구현 기록은 [CHANGELOG.md](CHANGELOG.md)를 확인하세요.

## PC가 꺼져 있을 때 수집

별도의 **비공개 저장소**에서 예약 수집하고, 로컬 앱이 실행될 때 비공개 스냅샷을 가져오는 기능을 제공합니다. 공개 저장소의 CI에서는 수집하지 않습니다. [CLOUD_SETUP.md](CLOUD_SETUP.md)를 참고하세요.

## 공고 분석과 유사도

- 고용 형태·지원 상태·백엔드/서버/인프라 필터, 지원 예정/완료 및 메모를 로컬에 저장합니다. 공고가 마감돼도 기록은 유지됩니다.
- 상세 화면에서 담당 업무·자격요건·우대·근무 조건과 원문 근거를 확인하고 2~4개 공고를 비교합니다.
- 현재 검색 조건 전체의 기술 요구를 집계합니다. 같은 기술이 여러 구분에 등장할 수 있고 출처 간 중복은 집계에 포함됩니다.
- 별도 분석 프로세스가 새 공고·변경 공고의 의미 벡터를 생성합니다. 진행 중 개발 공고를 먼저 처리하고 나머지 저장 공고도 이어서 처리합니다.
- 유사 공고는 코사인 유사도와 공통 기술·비슷한 문장 근거를 보여줍니다. 점수는 지원 적합률이나 합격 확률이 아닙니다.
- 중복 후보를 검토해 출처 링크를 묶거나 해제할 수 있습니다. 원본 공고·지원 기록은 삭제하지 않습니다.

분석에는 [FastEmbed](https://qdrant.github.io/fastembed/)와 [multilingual MiniLM](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2)을 사용합니다. 최초 실행 시 공개 모델을 내려받고 이후 공고 본문 임베딩은 PC에서 계산합니다. 모델은 Apache-2.0이며 FastEmbed의 양자화 ONNX 배포를 사용합니다. 모델 다운로드 연결이 없거나 분석 패키지가 없으면 색인 대기/오류를 표시합니다. 예약 수집에는 분석 패키지와 모델이 필요하지 않습니다.

벡터는 원문 변경 시 다시 계산하며 생성 중인 공고나 오래된 벡터를 최신 검색 결과인 것처럼 사용하지 않습니다. 기존 SQLite DB에 파생 테이블을 추가하므로 원문과 로컬 기록을 유지합니다. 분석 중에도 검색 API는 별도 프로세스에서 응답합니다.

이력서·포트폴리오 업로드/개인 경험 추천, Markdown/HTML/PDF 리포트 내보내기는 아직 포함하지 않습니다.


## 공고를 찾아 비교하는 순서

1. **내 기술로 공고 찾기**에서 기술을 눌러 선택하고 저장·적용합니다. 기술 이름을 직접 입력하는 대신 목록 검색으로 태그를 찾을 수 있습니다. 하나 이상 언급/모두 언급 조건은 기술 언급을 기준으로 하며, 모든 자격요건을 충족했다는 뜻은 아닙니다.
2. 진행 중·국내·신입/주니어와 백엔드/서버/인프라 등 원하는 필터를 조합합니다. 경력을 확인하지 못한 공고는 별도 포함 여부를 선택합니다. 필터는 저장된 공고를 보여주는 조건이며 원본을 삭제하지 않습니다.
3. **마감일순**으로 지원 순서를 정합니다. 확정 마감일이 없는 상시·미확인 공고는 날짜가 있는 공고 뒤에 표시됩니다. 원문에서 확인된 마감과 날짜 경과에 따른 마감 판정을 함께 사용합니다.
4. 상세 화면에서 업무·필수/자격요건·우대·일반 언급과 원문 문장을 확인합니다. “한 가지 이상” 같은 대안 조건과 비필수 표현을 구분합니다. 구역을 찾지 못했다는 안내는 해당 조건이 없다는 뜻이 아닙니다.
5. **유사 공고**에서 현재 직무·경력·지역 등의 조건에 맞는 후보와 비슷한 문장 근거를 확인합니다. 색인이 준비되지 않은 공고는 대기로 표시하며, 유사도는 지원 자격이나 합격 확률로 해석하지 않습니다.
6. 목록 왼쪽에서 2~4개를 선택해 **비교**합니다. 공통 기술과 각 공고의 조건을 확인하고 즐겨찾기·지원 상태·메모를 저장합니다. **중복 후보**는 검토 후 같은 공고로 묶거나 다른 공고로 표시하며, 묶음을 풀어도 원본과 지원 기록은 유지됩니다.

기술 요구 통계는 현재 페이지뿐 아니라 검색 조건에 맞는 전체 저장 공고를 대상으로 합니다. 필수와 우대에 같은 기술이 나타날 수 있고, 여러 출처의 같은 공고가 포함될 수 있습니다. 원문에서 확인한 사실과 추출 결과를 함께 살펴보세요.

## 업데이트 후 확인

소스 파일을 바꿔도 이미 실행 중인 Python 서버에는 변경이 적용되지 않습니다. 작업 중인 수집이 끝난 뒤 기존 앱을 정상 종료하고 같은 실행 방법으로 다시 켭니다. 기존 DB를 삭제하거나 빈 DB로 교체할 필요는 없습니다. 시작할 때 필요한 파생 분류를 갱신하고, 분석 워커가 내용이 바뀐 의미 색인을 이어서 만듭니다.

화면의 의미 색인 수와 대기 수를 확인하세요. 새 규칙으로 다시 분석하는 동안 일부 유사 공고는 일시적으로 대기 상태일 수 있습니다. 원문·즐겨찾기·지원 기록과 파생 분석 데이터는 구분해 보존합니다. 수집 경로의 접근 제한, 아직 처리하지 않은 주소, 확인하지 못한 조건은 완료로 표시하지 않습니다.


## 목록 화면

공고는 회사·제목, 경력·근무 조건, 마감, 저장을 일정한 열에 배치합니다. 모바일에서는 조건과 마감이 제목 아래로 이어집니다. 목록 표시에서 간결한 행과 본문 미리보기를 선택할 수 있습니다. 제목을 누르면 상세 분석을 열며, 기술 구분 근거와 지원 기록은 펼쳐서 확인합니다. 수집 관리·일시정지·백업은 상단에 항상 표시됩니다.

정보 정렬과 선택·필터 상호작용은 [shadcn/ui Data Table](https://ui.shadcn.com/docs/components/base/data-table), [Tabler Table](https://docs.tabler.io/ui/components/table)을 참고했습니다. 기존 HTML/CSS/JavaScript에 맞춰 구현했으며 해당 프레임워크나 외부 CDN, 폰트, 추적 코드를 추가하지 않았습니다. 참고 오픈소스: [shadcn-ui/ui](https://github.com/shadcn-ui/ui), [tabler/tabler](https://github.com/tabler/tabler).


## 개인 문서 추천과 리포트

상단 **내 문서·추천**에서 PDF/TXT/Markdown 이력서·포트폴리오를 추가하고 추출된 내용을 확인·수정할 수 있습니다. 문서는 버전 이름으로 묶어 선택합니다. 별도 분석 워커가 의미 벡터를 갱신하며, 수정된 문서는 새 색인이 준비되기 전 추천에 사용하지 않습니다. 문서·벡터는 로컬 experience.sqlite3에만 저장하고 클라우드 스냅샷/공개 저장소로 전송하지 않습니다. 데이터 백업에는 개인 문서도 포함되므로 백업 ZIP을 비공개로 보관하세요.

목록의 경력·직무·근무 국가·지역·기술 조건을 먼저 적용한 뒤 선택 문서와 공고의 의미 유사도를 비교합니다. 공고 문장과 경험 문장을 나란히 확인하고 필수·우대 원문에 맞춰 본인 역할·설계 선택·검증 결과를 보완하세요. 유사도는 지원 적합률이나 합격 확률이 아니며, 문서 미기재가 경험 부재를 의미하지 않습니다. 문서의 문장은 실행 지시로 취급하지 않습니다.

개별 공고·비교·검색 기술 분석·경험 추천에서 **리포트**를 열고 Markdown/독립 HTML/PDF로 저장합니다. 개인 경험 리포트에는 문서 내용이 포함됩니다. 한글 PDF는 Windows의 기본 한글 글꼴을 사용하며 다른 환경에서는 `RADAR_PDF_FONT`에 배포 권한이 있는 한글 TTF 경로를 지정할 수 있습니다. 설치는 `pip install -e ".[analysis,documents]"` 또는 기존 `start.ps1`을 사용합니다. 스캔 PDF에는 OCR을 적용하거나 텍스트를 붙여넣어 주세요.

## 제한된 주기 QA

`POST /api/qa-schedule`은 마지막 수집이 성공한 공개 ATS 대상으로만 60~600초 간격, 최대30분의 QA를 설정합니다. 종료 시각을 로컬에 저장하므로 재시작 후에도 만료를 확인하고 24시간 주기로 복귀합니다. `DELETE /api/qa-schedule`로 조기에 종료할 수 있습니다. 429 휴식·접근 제한의 재시도 간격은 단축하지 않습니다. 제한 시간에 끝나지 않은 수집은 무한 반복하지 않고 다음 예약에서 이어갑니다. 짧은 주기의 반복 QA는 실제7일 운영 기록과 별도로 기록합니다. Private Actions의 기본 일정은 하루1회입니다.

기존 서버를 보존한 업그레이드에서는 로컬 `data/active-runtime.json`이 새 데이터 폴더와 포트를 지정할 수 있습니다. `start.ps1`은 프로젝트의 data 하위 디렉터리인지 확인한 뒤 해당 운영 버전을 실행합니다. 이 전환 파일과 운영 데이터는 공개 저장소에 포함하지 않습니다.
